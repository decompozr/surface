# Consumers and scope

Status: consolidated current intent for the bounded Surface Web runtime, from [vision](../intent/vision.md) and the existing [page contract](../../skills/surface/references/pages.md). These identifiers support evaluation; they do not introduce a domain product.

| ID | Required behavior | Boundary and verification |
| --- | --- | --- |
| <a id="r-01"></a>R-01 | A Git project can own ordinary interactive source and domain meaning, mount it, and use Surface without DecompozR services. The experience declares whether input previews, proposes or requests a change. | Core owns identity/runtime/exchange, not financial formulas, CAD rules, intent confirmation or project orchestration. [Consumer evaluation](../evaluations/consumer-eval.md). |
| <a id="r-02"></a>R-02 | New/updated user-facing previews use declared `routes` with `+page.svelte` components and returned readable workspace URLs. Read-only browsing needs no request/binding. Agent submission uses the exact request URL and scoped capability. | Route conventions do not support arbitrary SvelteKit applications, layouts, load functions, server actions, SSR or dynamic route parameters. Legacy component catalogs remain compatibility behavior. [Navigation design](../design/navigation.md). |

Inquiry may consume Surface just as another project can. Its research process, evidence interpretation, trade proposals, data model and authorization policy belong to Inquiry. No Inquiry implementation, integration run or domain evaluation is established here. A future Inquiry evaluation must name its own source contract and use the same Surface identity, submission and result boundaries; it cannot be inferred from generic fixture success.

Other possible consumers include a design comparison, architecture explorer or simulation view. These examples express intent, not built-in capability commitments. Multi-user collaboration, public hosting, untrusted-code execution, native renderers, arbitrary frameworks and generic autonomous agents remain excluded from the current contract. Private Tailscale browser access is a bounded source-setup feature; it does not establish remote management or agent connectivity.
