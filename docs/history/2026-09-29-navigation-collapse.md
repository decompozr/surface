# Navigation disclosure verification

The September 29 user request adds independent expand/collapse to workspace/project, worktree and folder groups. The prior provider NavigationLinks rendered noninteractive group labels and every child list unconditionally, so these actions were unavailable. The adopted behavior is in [navigation](../design/navigation.md#expandable-groups).

Provider main `e3aea6c` adds a public controlled disclosure API. Provider `check` and `package` passed with zero diagnostics. The Surface working tree based on `b3ebc0b` consumed those exact packaged sources for `bun tests/e2e/surface/verify-navigation-collapse.ts`: isolated registered main/linked worktrees, project/worktree/folder collapse, native keyboard activation and refresh restoration passed in desktop Chromium 1440×1000 and touch-emulated Chromium 390×844. No user installation, recipient or conversation was mutated.

Visual inspection of the expanded phone and collapsed desktop states found consistent 32px row cadence, distinct project/worktree/folder/page icons, readable labels and no overlap. Keyboard focus is visible after keyboard activation and remains separate from expansion. Screenshots are temporary release-review evidence under `/tmp/surface-editor-review/navigation-*.png`; retire them after the integrated release audit. Physical phone acceptance and the final installed release are separate gates owned by integration.

## Related geometry verifier migration

The retired selected-element four-action toolbar assertions were updated to the two-action draggable Comment/Screenshot toolbar. The new checks retain roving keyboard coverage, icon and target dimensions, pane/content geometry, touch scrolling and edge gestures, capture/composer bounds, focused draft retention and synthetic keyboard resize/pan. Fixed toolbar position during page scrolling replaces obsolete anchor-tracking expectations; pointer/keyboard movement, persisted position and viewport clamping are additional checks. Desktop navigation now docks immediately, so the old intermediate slide-position expectation is kept only for phone overlays.

On the same September 29 Surface WIP, an isolated immutable production-plus-fixture snapshot passed `toolbar-scroll.e2e.ts` in Chromium/WebKit, `mobile-desktop.e2e.ts` in desktop Chromium/touch Chromium/iPhone WebKit, and `viewport.e2e.ts` in Chromium/WebKit. Phone pane and keyboard/capture screenshots were inspected: controls remain contained, the saved draft is visible, and the capture editor keeps input and actions reachable. Synthetic viewport movement does not establish physical iOS keyboard behavior. Temporary evidence `/tmp/surface-geometry-current` is retained until the final release audit and then should be retired; no fixture delivery reached a real conversation.

### Restored mobile pane focus-scroll regression

The integrated mobile reload check found a provider containment bug: the outer AppShell grid, styled `overflow:hidden`, accepted programmatic horizontal scrolling when focus moved into the entering pane. WebKit recorded shell `scrollLeft=302`; pointer focus then reset it to zero between pointerdown and pointerup, moving Close away from the pointer. Provider `8d1e672702060ad9d1515eb3d6d9c250640a6df1` changes only the outer grid to `overflow:clip`, retaining main/navigation internal scrolling and focus behavior. Provider check/package passed. The comments verification agent ran the exact mobile queue regression against the candidate package: reload shell offset stays zero, one Close activation hides the pane, two batches queue independently, and drag/position restoration/resize/screenshot-add checks pass. The integrated release matrix remains the final gate.
